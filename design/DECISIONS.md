# Design decisions

Decisions about anything a user sees or types: the owner's answers to the previews in
`design/preview/`, and — since the owner put the project under Claude's management on
2026-11-25 — the choices Claude makes where the approved design is silent. Each row gives
the reason, so a later session can tell a considered choice from an accident. A decision
here is changed by adding a row, not by building something different.

| 2026-11-25 | What "repeatable" promises | A deterministic run (the default) returns the same result **for any number of threads, on any platform, for any memory budget and whichever way the planner executes it** (in memory or out of core; a view as a mask or materialized). The planner never substitutes a lower-precision variant by itself: it refuses and offers it. Not covered: results cut short by `timeout`, and `deterministic=False`. *"Trust it" means the budget is a question of time, never of answer. This is wider than D14 (threads, platforms): the kernels' issues gain identity tests across regimes and #45 is amended; if a kernel cannot meet it the promise is narrowed by ADR, not silently.* | decided by Claude |
| 2026-11-25 | What "repeatable" promises, for files built by appends (ADR 0028) | Added to the row above: **for a file built by appends, results depend on its batches, not on how they are stored: merging or compacting segments never changes a result.** Segments are not in 0.1 (#111); the sentence is written now so that the format of 0.1 keeps it possible. *It follows from fixed reduction ranges (not file blocks), byte-identical merges, exact pair sums across runs and a graph order that grows by appending (ADR 0028), and it is the promise a user of a daily-appended graph would test first.* | decided by Claude |
| 2026-11-25 | Default weight for PageRank and communities | `weight=True`: the column declared at `eg.read(weight=…)` summed over a pair when one was declared, otherwise the number of edges between the pair. The result always says which was used; `weight=False` ignores both. *A column the user declared is an instruction, not a guess; saying it in the result covers the surprise on transfer graphs dominated by a few large amounts.* | decided by Claude |
| 2026-11-25 | Time windows | Closed at both ends. A date without a time (`"2024-03-31"`, `datetime.date`, a day-unit `datetime64`) means the whole day; anything with a time is an instant; naive times are UTC; an integer is compared in the column's own unit (block number, epoch). *Makes the approved `g.window("2024-03-01", "2024-03-31")` mean March, as pandas users expect; a `closed=` option can be added later without breaking this.* | decided by Claude |
| 2026-11-25 | Nodes in a view | Filtering edges or taking a window keeps only nodes that still have an edge; filtering nodes or `subgraph` keeps the edges among them. Degrees inside a view are the view's. *Communities of one month should not report two hundred million isolated nodes.* | decided by Claude |
| 2026-11-25 | What a shared map reveals | `reveal=` is **required** when a map is written for sharing (`m.export(path, reveal="full" \| "summary")`, `everygraph map --out FILE --reveal …`); there is no default. The working map that `g.map()` / `everygraph map` keeps beside the graph is full. *`choices.md` C3 says "choose at export"; a silent default would publish every identifier by omission.* | decided by Claude |
| 2026-11-25 | Exit status for "no such node" | `UnknownNode` gets its own exit status, **6**; 2 stays for usage errors, bad expressions and unsupported operations. In Python it derives from `LookupError`, not `KeyError` (which quotes and mangles a multi-line message). *A script looping over identifiers must tell "not in the graph" from a typo in the command.* | decided by Claude |
| 2026-11-25 | Degree columns | `in_degree`, `out_degree`, `degree` (distinct neighbours), instead of `in`, `out`, `total` as sketched in `api.md` § 2. *`in` is a keyword of the filter grammar and of Python; a pair is analysed once (`choices.md` A1), so a degree counts neighbours, not events.* | decided by Claude |
| 2026-11-25 | Identifiers in results | The `node` column has the type of the input column. Text recognized as hexadecimal and stored as bytes comes back as lowercase text with the prefix the input used; look-ups accept any case. *Joins with the user's own tables must not fail silently on mixed-case addresses.* | decided by Claude |
| 2026-11-25 | Where scratch goes | By default in a hidden directory beside the output file, not the system temporary directory; `--temp-dir` / `temp_dir=` / `EVERYGRAPH_TEMP_DIR` override. Scratch on a memory-backed file system counts against the memory budget in the preflight. *`/tmp` is RAM on many distributions: 61 GB of "scratch" there would break "never run out of memory"; the output's file system is also where the final rename is atomic.* | decided by Claude |

| 2026-11-25 | Review of the API by an outside practitioner (#12) | The sketch is merged on the independent review alone; the review by outside practitioners is part of the pre-launch review (m8-08, release 0.1) and **gates the freeze of public names at 0.1**, not the start of implementation. *Finding the person needs the owner's hands and, in practice, a public repository; blocking forty issues on it would trade a real schedule for a formal one.* | decided by Claude |
| 2026-11-25 | Graph semantics, as the correctness oracle checks them (`oracle/SEMANTICS.md`, Q1–Q13) | On a directed graph `degree` is the number of distinct neighbours in either direction — the degree in the undirected projection — not `in_degree + out_degree` as NetworkX and igraph define it (a reciprocal pair is one neighbour). Core numbers, triangles, clustering and transitivity of a directed graph are computed on that projection, which sums the events of both directions. A kept self-loop adds 2 to the undirected degree and 1 to each of in- and out-degree; repeated rows of a pair count once, with weights summed for PageRank and the minimum taken for shortest paths. Clustering at degree below 2, transitivity without a triple and modularity without edges are 0, never NaN. A component's internal label is its earliest node (the API then numbers components by size). Traversals follow out-edges unless `direction=` says otherwise; an unreachable node has no value. PageRank is the fixed point, whatever the iteration count. PageRank and core numbers with kept self-loops are defined by #36. *One projection for everything that ignores direction (communities, k-core, triangles, `degree`, hubs), so the numbers a user sees on one graph agree with each other; where the libraries disagree with each other we follow the one that returns a number.* | decided by Claude |
| 2026-11-25 | How the project is run, for speed | After a discussion with the owner: up to about eight agents at once on every ready issue; official measurements batched into short windows while development continues outside them; decisions from interleaved A/B runs, an empty machine only for published numbers; review in three tiers by risk; a thin end-to-end slice first, with a dogfood pass at each milestone; code kept small, a test audit with `cargo-mutants` at each milestone. Rules in `CLAUDE.md` §4 and §6. *The owner asked for faster execution without losing quality, and worried about code and test bloat and about process for its own sake.* | decided by Claude, discussed with the owner |
| 2026-11-25 | Graph semantics, the cases left to #36 (`docs/spec/graph-semantics.md`, PR #145) | One principle: a kept self-loop is a pair {v,v} of weight w, entering the adjacency as A[v][v] = 2w on an undirected graph (and on the undirected projection) and w on a directed one. **Volume and flow measures** count it through that matrix — degree (+2, Q1), strength, PageRank (as igraph and PRPACK; NetworkX counts w), modularity (as both libraries; Leicht–Newman and CPM likewise), and the quotient graph, which carries input loops on its diagonal. **Cohesion and reachability measures ignore it** — core numbers (NetworkX refuses loops; igraph would make a lone looped node a 2-core), triangles, clustering and transitivity with k′ = neighbours other than itself, components, traversals. Also: loops are treated before duplicates; an identifier whose only rows were dropped loops stays as an isolate; `duplicates="sum"` analyses as "events" (multiplicity from the `edges` column) and `window()` on it is `Unsupported`; a pair's weight is the exact sum of its events rounded once to f64; exact integer/decimal sums stay exact (decimal128/256), overflow is `InvalidInput`; column statistics at build are count, nulls, NaN, min, max, sum and the largest pair multiplicity; reported sums (degrees' `weighted`, `neighbors()`, `to_scipy()`) never refuse; `to_scipy()` puts w on the diagonal so it round-trips with NetworkX. *Consistency: modularity must be equal before and after Louvain/Leiden aggregation, which turns a community's internal edges into a loop — so input loops must count the same way; a k-core is about ties to other nodes.* | decided by Claude |
| 2026-11-25 | Memory-mapped files are read through a safe constructor | `everygraph-io`'s `MmapSource` stays a safe API, under a recorded invariant: Everygraph maps only files it wrote itself and never writes again (graph files, spill files, stores), and no writer — another process or this one — may modify or truncate a file while it is mapped; violating it is undefined behaviour or SIGBUS, and is not enforced against other processes. Inside the process the sinks refuse to create, truncate or write a file (by device and inode) that a live `MmapSource` holds. The SAFETY comment and the docs state exactly this. *A safe map is the convention of the Rust ecosystem for read-only data files; making every caller `unsafe` would push `unsafe` into kernels, which the project forbids, while the in-process guard closes the one hole safe code in this workspace could open (review of PR #151).* | decided by Claude |
| 2026-11-25 | When the repository becomes public | **Now, during development**, instead of at 0.1 (`choices.md` D1). The owner: showing a work in progress does not matter to him; a self-hosted runner is worse than publishing; the project is open source and non-profit; the trademark application and the patent check (`docs/legal/`) are risks he accepts. Publishing also ends the Actions-minutes problem (public repositories use GitHub-hosted runners, macOS, Windows and ARM included, at no cost). Claude audited the history before (no secrets or tokens, no dataset redistributed, bundled fonts carry their OFL licences; commit metadata contains the owner's git e-mail). The visibility change and the first registry uploads are done by the owner: the guard rails deny them to Claude. | **decided by owner**, risks acknowledged |
| 2026-11-25 | Identifier columns: hex prefixes, UUIDs, stray keys | Hex keys come back lowercase, with `0x` when the input used a prefix (`0x` or `0X`) and with none otherwise; UUIDs come back lowercase, hyphenated, and are looked up in any case. A key that does not fit the column's detected kind (an empty or `"0x"` address in a hex column) is an **invalid row**, reported with its line like any other, not a reason to reinterpret the whole column as text; `ids="string"` keeps every key as text. *One stray value must not change the identity of every node (review of PR #158: one bad key turned 155,184 nodes into 205,047).* | decided by Claude |
| 2026-11-25 | The memory promise covers the process, not only the ledger | The budget bounds the process's anonymous memory, measured by the cgroup — not just the accountant's books. Allocator retention (glibc arenas kept 1.2–2.3× the budget in the review of PR #158) is the accountant's responsibility: an allocator policy for the engine is issue `m2-19-allocator-policy`. Until it lands, acceptance boxes say "ledger within budget" and report the measured anonymous peak beside it. | decided by Claude |
| 2026-11-25 | The map's super level | Built when the partition T needs more than 63 communities to cover 90% of the nodes; on a rebuild of the same dataset, hysteresis — switched on above 72, off below 56, otherwise the previous decision kept. Not always-on: an always-built super level costs the drawn top level 2.5 points of modularity on lj, 7.5 on Friendster and 14.7 on orkut (#19, PR #162, exploratory). *A deliberate discontinuity, with measured margins (lj 14 below, orkut 53 below, Friendster 57 below, web-google 28 above, roadnet-ca 256 above) and no flip under six perturbations once Leiden's stopping test ignores isolated vertices.* | decided by Claude |
| 2026-11-25 | Label propagation follows LDBC CDLP | Label propagation (#65, `plan/issues/m4-09-label-propagation.md`; its public name is chosen when it is built, `docs/api-sketch.md` § 7) is synchronous label propagation with LDBC Graphalytics CDLP semantics: each node's initial label is its position in the original key order, and ties go to the smallest label. It is never a low-budget fallback for Leiden. A relabelling of stored ids (#146) must keep id-dependent semantics on the original ids: CDLP labels and ties, min-label components, BFS from a given source. *Our earlier tie-break by label hash differed from the only standard deterministic LPA, so our results could not be checked against LDBC's reference outputs. CluStRE, the earlier fallback candidate, has a 10-minute wall-clock cut-off in its local search, so it is not deterministic (`docs/research/README.md` A5; `docs/research/memory-bounded-algorithms.md` addendum item 17; `sota-communities.md` § 3).* | decided by Claude |
| 2026-11-25 | Memory maps and I/O errors (amends the safe-mmap row above) | The planner maps only files on local block devices; every other file (network or removable file systems, FUSE) is read through `FileSource`. The SAFETY comment and the docs of `MmapSource` add: a media or device error under a map ends the process with SIGBUS, where `pread` returns EIO. Warming regime 1 uses `MADV_POPULATE_READ` where available, which returns an error instead of raising a signal. *The recorded invariant covered modification and truncation, not I/O errors (Crotty et al., CIDR 2022 § 3.3, as read in `docs/research/sota-io-memory.md` § 3; `docs/research/README.md` A8).* | decided by Claude |
