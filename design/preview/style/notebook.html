Notebook

What Everygraph objects look like when a Jupyter cell displays them, in JupyterLab’s light and dark themes, and what the same objects print in a plain Python prompt.

Rules for outputs

JupyterLab keeps its own look. Everygraph draws only inside the output area, and there it follows the same tokens as everything else.

One object, one card

Hairline border, 6 px radius, no shadow, at most 800 px wide. Only the map uses the full width of the cell.

The notebook’s theme decides

Cards follow JupyterLab’s light or dark theme, never the operating system’s. The map canvas stays dark in both, as in the viewer.

Exact numbers, in monospace

Counts are exact with separators. A table that shows fewer rows than exist says how many, in its footer.

Progress is ink, not accent

The bar is a plain fill in the text colour with the phase name, the rate and the time left. Done adds a tick and the word.

Errors give the arithmetic

What, why with the numbers, then the ways out as code that can be copied. The traceback is folded.

Text says the same

Every card has a plain-text form with the same facts in the same order, for a terminal, a log or a diff.

Text equivalents

What the same objects print at a Python prompt, in a log or under print(). Same facts, same order, no colour needed; lines stay within the terminal page’s width. Bars and box characters fall back to ASCII where the terminal cannot show them.
