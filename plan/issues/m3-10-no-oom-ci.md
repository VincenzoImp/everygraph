**Why.** "Never run out of memory" must be a tested property, not a hope. The lab showed file-backed pages never cause an OOM kill; anonymous O(n) state does.

**Built.** The suite is `crates/everygraph-memtest`, from PR #251. It runs every operation as the command line calls it: ingest, the dictionary, PageRank, BFS (with and without parents), SSSP, WCC, k-core, degrees and Leiden, each mapped and streamed, then `verify --deep` and `compact`. It runs them in process under a counting allocator, and in a `systemd-run` scope. Job `no-oom` in `ci.yml` runs the nightly part on a GitHub-hosted runner. There is no self-hosted runner (`design/DECISIONS.md`, "When the repository becomes public"). Known findings are listed in `everygraph_memtest::ops::KNOWN`, each with its issue ({{#m3-28-ingest-first-pass}}).

**Scope**
- [x] Test matrix: kernel × graph × budget ∈ {0.5, 1, 2, 4, 8 GiB, unlimited} × regime, each run inside a cgroup scope with `MemoryMax = budget + fixed slack` and `MemorySwapMax=0`
- [x] Expected outcomes are exactly two: success within the limit, or a clean `InsufficientBudget` refusal before work starts. The refusal is checked "before work" where a minimum is declared: ingest's estimate, and the minimum of {{#m3-02-planner}} for each kernel of `run` on a mapped graph (`Op::declared_minimum`)
- [x] Record accountant peak vs cgroup anonymous peak; the gap is the "untracked memory" metric and must stay below the slack
- [x] Also record, per run, the kernel terms of `memory.stat` (`pagetables`, `kernel`, `shmem`) and `memory.events` `oom_kill`. The counting `GlobalAlloc` below is approximate, because the compiler may elide allocations (GlobalAlloc docs); the cgroup record is the ground truth (`docs/research/sota-io-memory.md` § 3, m3-10 row)
- [ ] The cgroup monitor of {{#m2-19-allocator-policy}} runs in every case of the matrix, once m2-19 builds it. A thrashing run must end as an early, explicit refusal that names a regime that would work, not as a kill
- [ ] The tracer's Leiden-16G case (killed at 460.5 s while thrashing) is one of the cases of the matrix
- [x] The cgroup matrix runs nightly on a GitHub-hosted runner, on generated graphs up to 2^22 nodes, for what only the kernel sees (allocator retention, {{#m2-19-allocator-policy}}; page cache against anonymous memory; thread stacks); a reduced matrix runs in regular CI
- [ ] Tier-2 real graphs in the nightly matrix. They are not on GitHub's runners: the job fetches them, or a datasets cache is added
- [x] Same harness reused for ingest ({{#m2-08-csr-build}}) and communities (Leiden, {{#m4-01-leiden-production}}); out-of-core Leiden ({{#m4-04-ooc-leiden}}) is added as an operation when it is built
- [x] A counting `#[global_allocator]` asserts that heap bytes stay within `budget.used()` plus a fixed slack: it catches the growth a lint cannot (`push`, `extend`, `collect`, `clone`) and needs no cgroup (review of PR #154)

**Budget fuzzing: search, not only a matrix** (added 2026-11-25, `docs/research/README.md` T2; `docs/research/sota-testing.md` challenge 3). The lab's only OOM was untracked anonymous O(n) state (WCC under 1 GB, FINDINGS), and #34's `build-500m` case was OOM-killed under `MemoryMax=5G` with a 4 GiB budget in the official run `bench/results/id-dictionary/20261125T220117Z-c855fdd77cf9.jsonl`. Untracked heap that grows with n has a signature visible at any size:
- [x] **Slope test.** Per kernel and per generator family, in one process under the counting allocator, n = 2^10 … 2^16: record U(n), the most heap in use beyond the ledger at the same moment, counted as *requested* bytes (allocator-independent; RSS stays with the cgroup job), and take its slope against n between the two largest sizes, so that a state that stops growing below them (the dictionary's sample of 4,096 keys) is counted as the constant it is. Each run takes a tight budget, 1.05 times the smallest that completes or the declared minimum, so that reserved headroom cannot hide untracked heap. U must be bounded by a constant, or by threads × per-thread buffers; any bytes-per-node slope fails. A slope of b bytes/node predicts b × 65.6 M bytes untracked on Friendster (an extrapolation, labelled as such). The sizes straddle the spill, chunk (2^16 entries) and segment thresholds. The generators include hubs, a long path, long chains, duplicates, sparse id ranges, isolates and many small components. Cheapest check: the lab WCC's state must show a slope of about 4–8 bytes/node and ≈ 0 without it
- [x] **Search.** Fitness = U(n)/n, the slope over the largest sizes, or heap peak / budget — byte counts from the counting allocator, never RSS or wall time. The space: generator parameters (Singularity-style components: add node, add edge, grow edge, self-loop, bridge, merge, update weight) plus hub size, number of components, path length, id sparsity, key length and type, duplicate multiplicity, weight columns, chunk size, threads and budget. A configuration that raises the fitness is kept even with no new outcome (MemLock). In CI: targeted-PBT hill climbing, fixed seed, 1–3 minutes on ≤ 10^4 edges; nightly: a longer search
- [ ] Nightly findings committed as patterns (recipes in `everygraph_memtest::graphs`) that CI replays at three sizes
- [x] **Per-phase maxima.** The accountant sets a thread-local phase tag at each reservation; the counting allocator keeps a per-tag maximum of untracked bytes, and the search keeps an input that raises any tag's maximum (PerfFuzz). Findings are deduplicated by phase, never by input
- [x] **Budget boundary.** Per (kernel, graph), binary-search the smallest budget that succeeds and compare it with the planner's declared minimum ({{#m3-02-planner}}): declared < true is an OOM in waiting, declared ≫ true a needless refusal (the ratio is reported). Below the declared minimum the refusal itself allocates O(1). The hook is `Op::declared_minimum`: it holds ingest's estimate and the planner's minimum for the kernels of `run` on a mapped graph; the other operations and regimes declare none yet
- [x] **Fail the k-th reservation** (DESIGN D2's fallible allocation): for k = 1 … K, `try_reserve` fails at the k-th call; every run ends in a typed error, with no panic, no leaked scratch file, and the accountant back at zero

**Acceptance**
- [ ] Zero OOM kills and zero "untracked > slack" results across the matrix for two consecutive weeks of nightly runs
- [x] The slope test passes for every kernel and generator family, and the reintroduced lab WCC state fails it. The canary is in the suite (`the_slope_test_catches_the_lab_wcc_state`): the lab's untracked `u32` per node is allocated next to WCC in the same measured run. A flag in WCC itself would ship a code path that only a test uses
- [x] Every k of the k-th-reservation sweep ends in a typed error with the accountant at zero
