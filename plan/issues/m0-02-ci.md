**Why.** Three properties are easy to lose silently: the wasm32 build, behaviour with a 32-bit `usize`, and memory safety of the shared-memory parallel code (the lab Leiden uses `unsafe` shared arrays and was never run under Miri or TSan).

**Scope**
- [ ] GitHub Actions matrix: Linux x86_64 + aarch64, macOS arm64, Windows x86_64; stable Rust
- [ ] `wasm32-unknown-unknown` build of `everygraph-core` and `everygraph-wasm` (single-threaded on stable; threaded build on the pinned nightly with the explicit linker flags from FINDINGS § G)
- [ ] A 32-bit target test job (`i686-unknown-linux-gnu`) to catch `usize` overflow in offsets
- [ ] Miri job for modules that contain `unsafe`; ThreadSanitizer job for the parallel kernels on small graphs
- [ ] `cargo deny`, clippy, rustfmt, docs build
- [ ] Cache strategy so a PR run stays under ~15 minutes

**Acceptance**
- All jobs green on `main`; a PR that introduces a data race in a toy kernel is caught by TSan
- The wasm job builds and runs a toy kernel (degree count over a generated graph) in Node and compares its hash with the native run; real kernels join this check in {{#m3-11-determinism-ci}}
