**Why.** Three properties are easy to lose silently: the wasm32 build, behaviour with a 32-bit `usize`, and memory safety of the shared-memory parallel code (the lab Leiden uses `unsafe` shared arrays and was never run under Miri or TSan).

**Scope**
- [ ] GitHub Actions matrix: Linux x86_64 + aarch64, macOS arm64, Windows x86_64; stable Rust
- [ ] `wasm32-unknown-unknown` build of `everygraph-core` and `everygraph-wasm` (single-threaded on stable). The threaded build on the pinned nightly with the explicit linker flags from FINDINGS § G moved to {{#m9-01-browser-tier}} on 2026-11-25: nothing uses it before the browser tier, and that issue holds the recipe
- [ ] A 32-bit target test job (`i686-unknown-linux-gnu`) to catch `usize` overflow in offsets
- [ ] Miri job for modules that contain `unsafe`; ThreadSanitizer job for the parallel kernels on small graphs
- [ ] `cargo deny`, clippy, rustfmt, docs build
- [ ] Cache strategy so a PR run stays under ~15 minutes

**Acceptance**
- All jobs green on `main`; a PR that introduces a data race in a toy kernel is caught by TSan
- **Portability canary, run on every push:** a job applies a probe that adds forbidden calls to `everygraph-core` — `std::fs` directly, file access through `std::path::Path` (`exists`, `metadata`, `read_dir`), a clock read (`Instant::now`, `UNIX_EPOCH.elapsed()`), a DNS lookup (`to_socket_addrs`), an inner `#[allow(clippy::disallowed_methods)]`, a `#[cfg(not(clippy))]` block, and a new I/O dependency (for example `walkdir`) — and requires each to fail. This keeps the rule alive even if `clippy.toml` is moved or its lists rot
- The normal dependencies of `everygraph-core` are checked against an allow-list (`cargo tree -p everygraph-core -e normal`); `cfg(clippy)` does not appear in the crate; `#![allow(unsafe_code)]` appears only in modules registered in `CONTRIBUTING.md`
- The wasm job builds and runs a toy kernel (degree count over a generated graph) in Node and compares its hash with the native run; real kernels join this check in {{#m3-11-determinism-ci}}

**Notes from building the workspace (PR #123).**
- Run the check list in `CONTRIBUTING.md` verbatim, plus an MSRV job (`cargo +1.85 test --workspace --locked`): clippy runs on current stable only, so an API deprecated there but missing on the MSRV will otherwise collide with `-D warnings`.
- Miri cannot run the default-feature tests: with rayon enabled it reports undefined behaviour inside `crossbeam-epoch` under Stacked Borrows. Use the three commands documented in `CONTRIBUTING.md` (no default features; the same on `i686-unknown-linux-gnu`, the only place tests run with a 32-bit `usize`; Tree Borrows with rayon).
- The portability rule needs both checks: clippy's disallowed lists catch `std::fs`, threads and clocks; the wasm32 build catches `std::os`. Neither catches the other's cases.
- Give each crate that must reach the browser its own `clippy.toml` and wasm32 build as it gains content; today only `everygraph-core` is enforced.
