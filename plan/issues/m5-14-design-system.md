**Why.** The approved visual style existed only as a preview (`design/preview/style/`): tokens in a CSS file, fonts beside it, 53 first-pass icons and the mark drawn inline and duplicated across pages. The viewer, the documentation site, the notebook outputs and the exported figures must all draw from one maintained source, or they will drift apart.

**Scope**
- [ ] A small package `design/system/` (npm `@everygraph/style`, private until the release): `tokens.css` as the source, and `tokens.json` generated from it for the terminal and notebook renderers (the command line's terminal styles and the Python text form read it)
- [ ] Fonts: Inter and JetBrains Mono (SIL OFL 1.1) with their licences
- [ ] The mark as vector files generated from the tokens: Nest (light, dark, one colour), Seal, and the heavier small Seal for 16 px and below; an SVG favicon that follows the system theme
- [ ] Icons: the preview's 53 icons as an SVG sprite
- [ ] The data palettes with their measurement and search tools (`design/system/tools/`), so any change is re-measured for colour-blind separation and contrast
- [ ] Checks in CI: the generated files match `tokens.css`; the measurements pass; no product stylesheet hard-codes a colour instead of a token

The rest of the brand files (wordmark outlines, lockups, app icon, social card, raster favicons, icon redraws and pixel tuning, font subsetting) are {{#m8-12-brand-files}}. Importing the package is part of each user's issue: the viewer ({{#m5-05-viewer-core}}), the docs site ({{#m8-02-docs-site}}) and the notebook cards ({{#m5-10-jupyter-widget}}).

**Acceptance**
- `design/system/tools/build.py --check` fails when `tokens.json` or a mark file differs from what `tokens.css` gives
- The contrast table (`foundations.html` §9) and the palette figures (`data.html` §1) are regenerated by `design/system/tools/measure.mjs` and pass
- The mark files render correctly at 12, 16, 20, 32 and 128 px in both themes, each at or above its minimum size (SPEC.md: Nest 20 px, Seal 12 px)
- `design/system/tools/lint_colours.py` fails on a literal colour in a product stylesheet

**Design reference (decided 2026-11-25, `design/DECISIONS.md`).** The system is the one in `design/preview/style/` (`SPEC.md`, `design/system/tokens.css`), approved by the owner.
