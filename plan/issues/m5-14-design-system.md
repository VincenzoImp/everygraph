**Why.** The approved visual style exists only as a preview (`design/preview/style/`): tokens in a CSS file, fonts beside it, 53 first-pass icons and the mark drawn inline and duplicated across pages. The viewer, the documentation site, the notebook outputs and the exported figures must all draw from one maintained source, or they will drift apart.

**Scope**
- [ ] A small package `design/system/` (published to npm as `@everygraph/style` at release): `tokens.css` plus the same values as JSON and as a Rust/Python constant table for the terminal and notebook renderers
- [ ] Fonts: Inter and JetBrains Mono (SIL OFL 1.1) subset to the characters used, with their licences
- [ ] The mark as final vector files: Nest, Seal, and the heavier small cut for 16 px and below; favicon set; app icon; social-card template; light and dark variants for GitHub
- [ ] The wordmark as outlines (the preview uses live text) and the horizontal and stacked lockups
- [ ] Icons: redraw the ones flagged in the preview (`community`, `node`, `path`, `share`, `colour`, `eye-off`), pixel-tune the set at 16 and 20 px, ship as an SVG sprite
- [ ] The data palettes with their measurement script (`design/preview/style/viewer-assets/tools/`), so any change is re-measured for colour-blind separation and contrast
- [ ] A check in CI that fails when a product stylesheet hard-codes a colour instead of a token

**Acceptance**
- The viewer, the docs site and the notebook cards import the package and contain no literal colour values
- The contrast table (`foundations.html` §9) and the palette figures (`data.html` §1) are regenerated by a script and pass
- The mark files render correctly at 12, 16, 20, 32 and 128 px in both themes

**Design reference (decided 2026-11-25, `design/DECISIONS.md`).** The system is the one in `design/preview/style/` (`SPEC.md`, `assets/tokens.css`), approved by the owner.
